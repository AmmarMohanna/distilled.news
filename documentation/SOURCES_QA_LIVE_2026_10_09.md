This is a snapshot of the isolated `distilled-news-sources-qa` Cloudflare Worker, D1 database, R2 bucket, and processing queue. It is not the shared staging deployment. All seven QA sources were disabled after the tests. The QA Worker's aggregate and per-operation paid-provider limits were returned to zero.

The X and LinkedIn Apify runs each had one HTTP 201 actor creation and later HTTP 200 status/dataset operations. Final QA reservation totals were $0.20 for TwitterAPI.io, about $0.25 for X Apify, about $0.25 for LinkedIn Apify, and $0.03 for one Zyte request. Reservations are conservative ceilings, not provider invoices. Later X polls were blocked by the budget fence. No Google Apify call was funded. The configured limit for every provider is now zero; historical reservation totals remain in D1.

The first live X response exposed a parser mismatch: `data.tweets` held 20 posts while the connector only read top-level `tweets`. The connector now accepts both forms and preserves the top-level pagination fields. A subsequent capped live poll produced 20 intake receipts with no new X Apify operation.

Repeated polls generated more intake receipts than distinct candidates before the storage fix: 1,146 BBC receipts for 48 candidates and 2,890 Google News receipts for 103 candidates at the recorded snapshot. Google News had 29 distinct raw response hashes across 30 snapshots; whole-feed hash suppression would therefore help little. The connector now remembers each accepted item fingerprint only after a durable resolved intake receipt, scoped to its feed revision and fenced by fetch sequence. Unchanged items in later RSS, Google News, Telegram, and webpage polls are omitted from the next handoff; changed content or source revision metadata still emits an observation. A repeated live webpage fetch produced zero new observations twice while retaining one canonical candidate. The older QA receipt rows remain as historical evidence; this test does not yet establish steady-state D1 cost at hundreds of feeds.

The QA Cron Trigger initially showed no firings. An isolated one-minute probe later recorded 129 firings, confirming that scheduled execution began after propagation. The authenticated QA maintenance endpoint was used during diagnosis. The temporary probe Worker and its QA-only table were removed afterward.

The existing authorized Telegram session resolved `@telegram` to stable channel ID `-1001005640892` without joining a channel. Telethon returned message IDs 1–3 in the first bounded batch, then advanced to 4–7 and 8–10 on later scheduled polls. A direct recent-range check returned IDs 456–460 with text. The public-page adapter returned IDs 458–460, with no safe cursor. These are different collection windows: they demonstrate Telethon's backlog access and the public adapter's recent-page limit, not a complete channel-wide recall percentage. Telethon is the primary route for authorized accounts; the public page remains a best-effort fallback with partial coverage. Live edit, deletion, session-expiry and recovery behavior remain unverified.

The approved webpage was `https://books.toscrape.com/catalogue/a-light-in-the-attic_1000/index.html`. Direct HTTP plus the VPS extractor produced one observation in 1,962 ms; a forced Zyte call produced one in 3,587 ms. Both fed the same candidate identity, yielding two intake receipts and one candidate before the later repeat probes. The paid call's $0.03 reservation is not an invoice. Website scheduling now tries direct HTTP, then Playwright, then Zyte only when a positive budget is explicitly configured. The live result proves direct and Zyte routes on this accessible page; it does not prove Zyte can recover a blocked site or that Playwright works against a live target.

The connector fingerprint table is an additive D1 migration (`0046_connector_item_fingerprints.sql`) applied only to the isolated QA database. Shared staging has not received this migration or deployment. All QA test sources are disabled, and all paid-provider limits are zero. Future production rollout should coordinate this migration with the parallel intake owner and run a longer, multi-source storage/latency measurement before continuous operation.
