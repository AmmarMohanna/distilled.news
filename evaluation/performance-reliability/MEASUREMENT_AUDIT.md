# Measurement audit at design time

Audit basis: `aya-performance-reliability-evaluation`, application commit `e77e0d9`. Re-audit these boundaries when the implementation changes. This audit is source inspection, not live performance measurement.

| Existing evidence | What it establishes | Limit and proposed treatment |
| --- | --- | --- |
| `apps/worker/src/v1-intake/acquisition-router.ts`, router base `acquiredAt: options.now()` | Timestamp recorded when this acquisition invocation constructs its result base | It precedes payload reading, HTTP/extraction and evidence acceptance. Keep the legacy field exactly, but never rename it extraction completion or intelligence availability. Add prospective start/response/acceptance observations separately. |
| `apps/worker/src/v1-intake/evidence.ts`, `receipt.decidedAt` / revision `acceptedAt` | Acceptance decision under durable source/revision identities | The timestamp is sampled before transaction commit. A retained acceptance receipt is a historical availability proxy, not exact first database visibility. Existing frozen exports used this proxy; preserve their bytes and label that basis. A future collector must observe commit/read visibility independently. |
| `apps/worker/src/v1-intelligence/schedule.ts`, requests and migration 0069 | Deterministic expected window boundaries, with relative origin or legacy local-calendar policy | Reconstruct the independent due-opportunity manifest from the effective historical feed configuration. Counting only existing request rows would omit missed scheduler invocations. Do not round away creation seconds/milliseconds or expand delayed windows. |
| `apps/worker/src/v1-intelligence/v3-window.ts`, frozen V3 input/results | Exact offered evidence, model routing, prior reader history, result and operation identities | A stored model result is not necessarily published. Replays must preserve each variant's own actual previously published reader text, not drafts, rejected outputs or another variant's history. A missing initial history is not proven empty history. |
| `packages/briefing/src/prepare.ts`, `selectPrior`, called with `EngineOptions.now()` | Current memory policy: up to 16 items, four recent, 21-day age filter | A replay executed weeks later can select different memory if it uses today's date. Pin the logical history clock to the replay window, preserve this selector and record its chosen IDs. Newly generated replay history needs explicitly virtual publication times plus separate real generation times; never backdate financial admission, leases or provider expiry. |
| `apps/worker/src/v1-intelligence/latency.ts` | Monotonic durations for one execution and its stage spans | Stages overlap, retry attempts differ, and `SUCCEEDED` means the callback resolved, not that a briefing became public. Do not add overlapping stage totals into wall time or count reused receipt calls as newly billed operations. |
| `publication_status.publishedAt` and edition `createdAt` in V3/publication | Persisted application publication timestamp and status | Assigned before the surrounding write/commit finishes. Historical recorded-publication latency can be reported as a proxy. Prospective end-to-end success needs a matching public-reader read-back, supporting IDs and state at that time. |
| `apps/worker/src/v1-intelligence/public-read.ts` and public edition API | Reader-visible edition/citation projection | A prospective controller can poll by exact edition ID; retain last negative and first positive observations, polling interval and errors. Publication visibility lies in an observation interval. A read today cannot reconstruct yesterday's exact visibility timestamp. |
| `apps/worker/src/push.ts`, `recordPushAcceptance(..., new Date().toISOString())` | Timestamp sampled after successful push HTTP response, before receipt commit | This is not the start of the batch: current source samples a fresh time after response. Record `ACCEPTED_BY_PUSH_SERVICE`, not delivered-to-device. Durable receipt absence after unknown response must not imply the request was unbilled or unsent. |
| `apps/worker/src/push-outbox.ts` | Subscription-version-bound receipts and eligibility/cutoff/ownership checks; coalesced acceptance | Use edition × eligible subscription version as the receipt unit, but count actual network sends separately. One coalesced request is not one request per edition. Without a consenting instrumented client, display/user-receipt latency is unavailable. |
| `apps/worker/src/v1-intelligence/model-spending.ts`, provider receipts/recovery, account ledger | Durable model reservations, reported settlements, unknown outcomes and identities | Count one canonical billed operation once, including failed/repaired work. Keep partial confirmed cost, unresolved recorded exposure, estimates and allocated infrastructure costs separate. A conservative reservation is not an invoice or universal billing bound. |
| Connector provider/daily ledgers, snapshots and operation payload references | Acquisition admission, provider attempts and durable captured payloads | Separate source collection from article acquisition. HTTP 200 is not readable exact-article acceptance. Paid source costs shared across feeds/windows require allocation once; unknown/unallocated amounts remain explicit. |
| Existing acquisition benchmark | Reusable isolated provider harness, fault doubles and raw/reference separation | Synthetic offline outcomes are not live provider success rates. Use adapters/evidence where compatible, not its standalone ledger as a replacement for product account settlement. Existing source-matching references are incomplete until independently reviewed. |
| Existing 95-window private export | Real retained input text/IDs and retrospective availability sequences | 565 acquired IDs, 817 occurrences, overlapping durations, 12 empty windows, 89 unassigned records; all pilot IDs recur. Raw repeats and changed text do not prove human-reviewed update/correction cases. This is development data, not held-out gold. |

## Prospective instrumentation needed

Add an isolated evaluation observer before changing product instrumentation. It must capture an independent expected-opportunity list; offered/actual dispatch times; extraction start/completion and visibility evidence; first public read-back with polling bounds; exact subscription eligibility and push acceptance; canonical operation/accounting joins; and backlog samples with explicit gaps. Store UTC wall-clock observations and same-process monotonic durations with their clock domains.

Add minimal product hooks only where external observation cannot establish the boundary, behind an isolated evaluation configuration. Keep them metadata-only, measure their overhead, and test their failure behavior. The observer must not become a source of publication authority or block production writes. Do not put raw article text, credentials, push endpoints or unbounded operation-ID labels in public metric streams.

Historical proxy rows may support a separately named retrospective analysis. They must not be mixed with prospective observations into one headline latency distribution. No migration, hook or live instrumentation has been implemented by this design phase.
