# Server operation

The unit is a template for the professor's 2-core / 8 GB Ubuntu VPS. Installation and real provider runs remain operator actions. The benchmark does not deploy the Cloudflare application.

1. Install Python 3.12+ with venv support, Node 24+, npm, Git and Chromium's OS dependencies. Check the installed Playwright version's supported distribution before choosing its browser package. From this package run `bash scripts/setup-server.sh` as the benchmark user. The script installs package dependencies and Chromium, then runs offline tests; it does not contact acquisition providers.
2. Put the repository at `/opt/distilled.news`, create the unprivileged `distilled-bench` user, and grant it access to the package's venv and Node packages. Create `/etc/distilled-bench` for configuration and `/var/lib/distilled-bench` for data, credentials/session storage and writable runtime files. The example unit expects these exact paths; edit them if your checkout differs.
3. Copy `credentials.env.example` to `/etc/distilled-bench/credentials.env`, fill it locally, and make it readable only by the benchmark user (mode 600). A populated credentials file and Telegram session must never enter Git. Use an absolute `TELEGRAM_SESSION_PATH` under `/var/lib/distilled-bench`.
4. Copy `configs/stage3-soak.json` to `/etc/distilled-bench/stage3.json`. Set `data_dir` to `/var/lib/distilled-bench/data`. Replace inputs and account settings, enable the selected candidates, set conservative account-confirmed spend ceilings, and add references. Use absolute paths for references. Do the pilot and controlled runs first using the main README.
5. Configure `PLAYWRIGHT_BROWSERS_PATH=/var/lib/distilled-bench/browsers` in the credentials/environment file, then install Chromium with that environment variable set as the service user. This avoids browser caches under a home directory hidden by `ProtectHome=true`.
6. There are two browser routes. `browser` (isolated) launches Chromium inside an unprivileged network namespace; the parent HTTP client fulfills GET requests with pinned address validation, and response cookies and non-GET requests are blocked. Ubuntu 24.04+ restricts unprivileged user namespaces through AppArmor, so check with `python -m bench server-check --config /etc/distilled-bench/stage3.json` as the service user. If `user_network_namespace` is NOT_READY, leave `browser` disabled and report it as not tested, or obtain a scoped administrator exception; do not remove isolation to make it pass. `browser_standard` uses ordinary Chromium networking, cookies and all request methods; enable it only after applying and verifying the per-user outbound egress firewall in the [A-to-Z guide, Section 4.5](../../../documentation/EXTERNAL_TESTING_A_TO_Z.md), with the user name changed to this unit's `distilled-bench` user if different. Then set `host_egress_firewall_confirmed: true`. Both variants block downloads, image/media/font loading, service workers and WebSockets.
7. Set `costs.server_monthly_usd` in the configuration. Run `server-check` and preflight as the service user with its environment loaded. Install the unit with `sudo install -m 644 ops/distilled-bench.service /etc/systemd/system/distilled-bench.service`, then `sudo systemctl daemon-reload` and `sudo systemctl enable --now distilled-bench`. This starts a live campaign; do it only after the account settings and budgets are ready.

Inspect with `systemctl status distilled-bench`, `journalctl -u distilled-bench -n 100 --no-pager`, and `python -m bench status --data-dir /var/lib/distilled-bench/data --run-id week1-r000`. The campaign parent ID is `week1-schedule`. Its heartbeat updates while waiting and during collection. The shared data directory carries the cumulative budget across runs; changing directories starts a separate budget ledger.

Stop dispatch with `python -m bench stop --data-dir /var/lib/distilled-bench/data --run-id week1-schedule`. This also prevents new work in its active child run. Local stop does not cancel remotely billed jobs: inspect and cancel those in the provider dashboard, record evidence, then reconcile. `systemctl stop` terminates the process; known remote IDs remain recoverable, unknown submissions require manual resolution. Re-running the identical schedule command resumes existing rounds without resubmitting completed jobs. To clear a deliberate parent stop, use `python -m bench resume --data-dir /var/lib/distilled-bench/data --run-id week1-schedule`, then restart the service; this only clears the parent's stop flag, and the schedule command resumes its children.

Use a shared ledger for separate source-cadence configurations. Only one dispatcher may own it at once; stagger runs or combine work. There is no hidden retry on lock contention. The sample service reserves at most 6 GB and 1.8 CPU cores for the process tree; measure actual load before changing concurrency. Reports include free disk, heartbeat age and a `resource_summary` of the dispatcher's process tree (Python, Node, Chromium). The dispatcher stops new work below the configured disk reserve, and after host available memory stays below `min_available_memory_bytes` or host CPU stays above `max_host_cpu_fraction` for `pressure_seconds` (recorded as `capacity_stop`). Because `MemoryMax` caps the cgroup below host memory, also check `journalctl -u distilled-bench` for OOM kills.

Back up data after stopping the dispatcher and closing SQLite, including `benchmark.sqlite`, any WAL/SHM files, `blobs/`, reports, and external gold references. Keep the data directory private: raw captures can contain personal information. Apply the project's research retention policy to these files after the campaign; no automatic deletion runs during an experiment.
