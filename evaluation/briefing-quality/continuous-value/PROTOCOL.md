# Continuous personalized news evaluation — offline protocol

Base92be8812, isolated research/continuous-value. Binding-budget branch, protocols, sources and negative findings remain unchanged and unexecuted. No paid inference, deployment, merge, production data or account access.

Research question: does the selected V4 Distilled.news system deliver a more relevant, accurate, non-repetitive and reliable reader experience over time than simpler LLM services?

## Design

Use actual V3core/V4prompt with current product invocation flags from current-engine.ts, no experimental extraction/composition architecture. Enforce the same experimental110-word ceiling for every arm; it is a research comparison constraint, not a claim about deployed hard limits. Use existing matchedSingle with V4prompt for strong one-generation editor. Every arm receives the same common final source/novelty/script validator; V4's own verifier/repair costs are additional and visible. All have equal complete eligible retained current sources, interests, output language, cutoff/schedule and access to their OWN prior published text. No seeded reader history, another arm's output or reference facts appear in model input.

Arms:
- V4 + shared durable publication/checkpoint support.
- Strong single generation + SAME durable publication/checkpoint support. Comparing these isolates editorial behavior, not infrastructure ownership.
- Simple scheduled single-generation service: same interests/source pool/budget/full own publication history/common factual guard, persistent publication idempotency, but no prepublication result checkpoint/automatic result recovery. This documents a particular minimal service capability configuration, not a claim that a simple LLM cannot have checkpoints. A matching shared-support run can give it those capabilities; any recovery benefit is attributed to infrastructure.

After a successful publication, append exactly its actual reader text, canonical item IDs and ACTUAL publication time using existing publishHistory. A drafted, rejected, failed or QUIET result cannot enter history. Update/correction targets must exist in that arm/profile's actual prior history. Scheduled tick processing includes pending recovery in simulated-time order. A stale checkpoint cannot publish against changed history after another edition commits. Unknown provider outcomes remain blocked and never automatically resent. Provider responses/financial records remain immutable even if a deliberately simpler application has no auto-recovery policy.

Use the real firstClockBriefingAt/livePublicationWindow helpers, a shared retained-evidence eligibility rule and identical fault calendar. Source observation/availability time is separate from publisher/event time. Every arm sees the identical source pool for a given profile/cutoff (including retained reports); histories diverge endogenously. This is a controlled retained-pool study, not a claim to reproduce every production acquisition admission rule. The eligibility horizon is fixed at the whole short sequence; publication dates are not inferred event times.

Publication/recovery in the portable harness is an explicit offline contract model, not a reimplementation/certification of D1/outbox/queues. Existing local Worker CAS/checkpoint/duplicate/unknown tests are executed separately against their actual implementations with scripted providers. Those demonstrate existing capabilities, not a comparative editorial quality advantage or production throughput. Do not label simulated delays/storage counts as measured Cloudflare latency/dollars.

## Dataset and pilot

New fictional source-grounded sequences, not prior exposed windows. Source-only expected atomic developments include independent event IDs, updates/corrections with parent facts, recurrent distinct incidents, repeated reports, irrelevant sources, delayed discovery and actual quiet opportunities. Multiple reader interests are evaluated against the SAME source chronology. Relevance/reference labels are fixed before output. Constructed controls remain separate from any later natural-news cohort; no real-world held-out set is currently certified.

It contains two interests/languages, late observation, known pre-dispatch failure, loss/interruption after completed generation, and duplicate delivery after commit. No deliberate provider timeout/UNKNOWN is purchased; that safety behavior is tested offline only. Common recovery delay120seconds is a simulated dispatch condition, not measured worker delay. ## Measurement

Per arm/profile record every frozen input, complete prior-before/after, source hashes, actual output/history, successful publication time, result reuse, attempts, fault phase, calls/tokens/cost and unresolved operations. Sources/references and clock/fault calendar are frozen separately. Generation and common verification costs are separated from diagnostic evaluation and operational accounting.

Measure cumulative accurate relevant units/eligible units; first delivery delay from first ELIGIBLE cutoff, separately from source acquisition lateness; relevant developments missed at horizon; correct update/correction linking to an actual reader item representing the parent; repeated facts/editions; false QUIET (not failure/rejection); factual/citation quality; total reader words, useful units per100words; publication completion, idempotency, delay, recovery and checkpoint reuse. Retrospectively invalidated claims retain their original attributed-source status, while the subsequent correction is a new expected unit. Superseded unreported facts are not demanded as current news, but an earlier miss is not erased from cumulative coverage.

The exact controlled reference matcher is a lower-bound diagnostic: known complete canonical/approved bilingual statements plus correct sources can be recognized. Other paraphrases remain UNKNOWN, not automatically false or omitted. Unknown history-to-fact mappings make link/repetition/false-QUIET conclusions uncertain. For real-model outcomes, use source-derived fact/claim assessments, independent GPT/Claude diagnostics and preserved disagreements; neither judge nor their agreement is truth. Report failure-aware bounds, complete denominators, unsupported/inconsistent assessments and operational failures. Do not pool claims/profiles/windows as independent event groups. With one pilot cluster, paired effects are descriptive and a population confidence interval is unavailable. Later independent sequences use equal-event-group intervals.

Go/no-go remains conservative: no source-confirmed material factual error, no duplicate publication or unknown-operation resend. A meaningful comparative gain must survive both reference uncertainty and matched event-group analysis; inherited10ppcoverage/+factual non-inferiority targets remain unestablished in a small pilot. End-to-end reliability differences are attributed only to documented differing capabilities. If the strong single service matches V4, report it. This system-level study is not a claim of universal compressor superiority.
