# Desktop browser zoom

The desktop layout is retained when page zoom increases after a desktop viewport has been observed in the current tab. A device-pixel-ratio change, stable outer window width, stable screen dimensions and proportional viewport shrink distinguish this from ordinary window resizing. A retina/Windows display scale alone does not activate the behavior. The baseline is kept in session storage so refreshing a zoomed page can retain it. A first visit already zoomed in has no reliable baseline: reset to 100% once, then zoom again.

During detected desktop zoom, app-owned stylesheet width/height media conditions use the baseline dimensions, and the root retains its baseline width. Horizontal body scrolling exposes enlarged content. Color, print, reduced-motion and pointer conditions remain native. Grid measurements pause rather than refitting to the smaller viewport. Native dialogs and menus continue to use the visible viewport. Resetting zoom, changing screen or resizing the browser restores native responsiveness. Phone and touch-only layouts remain unchanged. Viewport-relative sizes can still change; this does not claim pixel-identical screenshot magnification or universally reliable browser zoom detection.

Validation: unit checks cover display scaling, monitor changes, resizing and media preferences. Chromium simulation changes viewport and device-pixel ratio together at 175%/200%, retains desktop controls and demonstrates horizontal panning, then restores responsive navigation on reset/ordinary resize. This is a simulated browser geometry check, not an automated click on Edge's native zoom toolbar.
