# Source search interaction

Typing now requests Google's public query suggestions after a short 150 ms pause. Only the typed prefix and interface language are sent; feed titles, descriptions and article text are never used to construct completions. Known publisher names provide a local fallback. These are suggested queries, never verified sources. No model or paid collector runs for autocomplete. Enter, a completion click or Search sources submits the full search. URL entry retains its explicit source-check flow.

The submitted request includes the current title and interests in an authenticated POST body. Search adds a bounded topic hint to upstream discovery, and indexed titles/excerpts must match both the query and topic gate before public access checks. Literal short subjects found in the interest description retain all subject words, preventing generic AI articles from matching the Ammar Mohanna feed. Generic titles fall back to meaningful interest words. This is a conservative lexical filter, not a claim of semantic or factual verification. The existing independent passage audit still decides admission. Rejected selections are removed and their reason is shown.

Search/discovery caches remain owner-scoped and now include the topic context. Changing the topic hides previous results; caches for another topic cannot supply article evidence to assessment. Existing blocked-source filtering and already-added publisher filtering remain in place. Searches with only off-topic indexed evidence show an explanation rather than source choices.

Suggestion requests have a 1.5-second deadline, a separate per-owner rate limit and owner-scoped caches. The public suggestion endpoint can become unavailable; failure does not fall back to copying feed descriptions. A new submitted web search can still wait for its upstream Google transport; cached searches retain the faster reuse introduced earlier. Existing Cloudflare request/cache/database usage applies; autocomplete introduces no paid provider or inference operation.

## Institutional pages and general discovery

Joud enables `SOURCE_RECOMMENDATIONS_WEB_HTML=true`. The public MSFEA researcher directory supplies actual profile links and their associated researcher cards. Multiword name searches check this index even without an AUB keyword. The public index is cached for fifteen minutes independently of user queries; result caches remain owner/topic scoped. Names and URLs are extracted from that first-party page; no individual profile URL is guessed or hardcoded. The search words and feed topic still gate each candidate. The discovered profile URL is retained as the source, so an institutional homepage error does not hide a readable profile. Source admission remains a separate check and is not implied by discovery. When every matching source is already configured, the UI explains that instead of leaving a blank result area.

Google News remains the retained fallback outside supported directories. Tested anonymous general-search endpoints were blocked or did not return usable results, so they are not used as an extra slow step. This is not a complete general web index; a supported search API would be needed for dependable broad coverage. Discovery cache version 5 invalidates earlier news-only empty responses.

## Approved general web discovery experiment

The operator-only `POST /api/admin/general-web-search-probe` runs one fixed three-query Google organic-search experiment through `apify/google-search-scraper` build `0.0.489`. It does not enable paid search for users. Invoke `node scripts/probe-joud-general-web-search.mjs --authorize-max-usd=0.10` only under the November 13 experiment approval; the fixed operation identity is deliberately not replaceable by caller input.

The dedicated `web_search_trial_20261113` provider budget and source budget enforce a $0.10 total reservation independently of the normal unlimited collection mode. The actor receives the same $0.10 ceiling, a 50-second timeout and no restart. AI searches, lead enrichment and article-content scraping are disabled. Durable HTTP retains the response in R2 and fences uncertain submissions. A missing response is not permission to create another run. The recorded ceiling is a conservative reservation, not an invoice. Search discovery does not establish public readability, feed relevance or source admission.

November 13 live outcome: the minified Worker deployment succeeded (`3d6972cf-94d4-4af8-9bd3-776300f796d2`). The single probe returned in 2.261 seconds with upstream HTTP 403, `platform-feature-disabled`: the Apify account had reached its $50 monthly usage limit. No organic result pages were returned and the actor was blocked from starting. D1 retains exactly one operation with a $0.10 ceiling and reservation; this is not evidence of an actual $0.10 charge. The error receipt is retained in R2. Do not reinterpret this account-level rejection as publisher blocking, clear the reservation, change the operation identity, or raise account billing limits without separate authorization. No ongoing paid user-search route was enabled.

The user subsequently approved increasing the account limit from $50 to exactly $50.10 and retrying within the original test allowance. `scripts/set-joud-apify-test-limit.mjs --authorize-monthly-limit-usd=50.10` applies only that bounded change and verifies it.
