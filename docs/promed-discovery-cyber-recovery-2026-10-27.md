# ProMED discovery and cyber-news recovery — October 27, 2026

QA branch: `aya-ghada-integration`; implementation commit `d801707`.

ProMED's public homepage contains a Next.js Flight `alerts` list and matching visible report rows, but no ordinary report anchors in those rows. Its public client uses `/alert/<alert_id>` links. Generic discovery missed these records, so HTTP, Playwright and Zyte attempts recorded `MALFORMED` despite successful page fetches. The scoped adapter parses data as JSON without evaluating JavaScript, supports split frames and Flight length-prefixed text preceding component records, validates positive numeric IDs and visible titles, preserves publisher issue dates (never substitutes creation dates), and emits listing candidates rather than full-article evidence. Captured real-page validation discovered 107 candidates. Archive completeness remains unproven and is marked unresolved.

The observed report URL `/alert/8735910` returns HTTP 307 to `/auth/login?returnTo=/alert/8735910`. The article HTTP adapter now classifies explicit same-origin login redirects as `AUTH_REQUIRED / ARTICLE_LOGIN_REDIRECT` before fetching the login page. Cross-origin/private-network guards are unchanged. Public discovery support does not grant authenticated/subscription access or turn homepage titles into full reports.

The Hacker News/FeedBurner and The Record failures were retry-exhausted jobs affected by the earlier shared-cache limit mismatch. Ten eligible cyber-feed jobs were reopened with the existing bounded operator API, one additional attempt each, under `qa-cyber-cache-recovery-20261027`. Prior failures, attempts, source identities and provider accounting remain intact. Follow-up found all five The Record jobs and two Hacker News jobs completed; the remaining three Hacker News jobs were waiting for helper capacity. This is an intermediate result, not a claim of complete recovery.

The old ProMED failed provider runs are immutable evidence. Reopening those exact runs would replay their saved failure attempts, so a fresh authorized collection was scheduled through `D1ProviderPollScheduler`, HTTP-only, under `qa-promed-public-discovery-fix-20261027`. It does not repeat the earlier Zyte purchases. Live QA verification retained the first 30 report candidates with offset 30 and no collection error; remaining snapshot slices continued through the normal queue.
