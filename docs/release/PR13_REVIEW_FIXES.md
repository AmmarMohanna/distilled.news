# PR #13 follow-up review

Base: `integration/beta-ui-extraction` at `2fb775ca`. These fixes are made directly on that PR branch.

1. Authentication records the verified session and closes the login dialog before loading personal feeds. Feed-list failure is handled by the existing Home error/retry state. Regression: login/session 200, first feed list 503, retry 200, one login only.
2. Product feed saves reuse the existing schedule validation and write SQL. Feed settings, all configured source rows, collection ownership, active-source removal, lifecycle fences and scheduler triggers commit in one D1 batch. A configuration/owner guard rejects concurrent changes. Source resolution and Telegram verification precede this transaction. A second-source database failure rolls back the entire save.
3. Enrollment follows the commit. If interrupted, the response is HTTP 202 with the fully saved briefing, `sourceActivation: pending`, and pending source IDs. The UI reports that the feed was saved and directs the owner to source health for pending activation. Source errors remain visible. When collection is enabled, existing durable source rows and scheduling triggers drive recovery, with both queue and legacy scheduler paths tested. Enrollment itself does not submit collection/model operations. Existing pre-save assessment and illustration scheduling policies remain unchanged. Existing scheduler idempotency owns later execution. A Worker termination or lost HTTP response can still leave a client uncertain about a committed request; retrying the same feed/source configuration preserves identities rather than duplicating sources.
4. Read history uses `dn_read:v2:` plus the reader account ID (or an explicit anonymous namespace), owner and slug. History is not read until viewer resolution finishes. Account/feed changes hide earlier IDs immediately, and guarded persistence prevents overwriting the next account's history. Invalid JSON, non-string arrays and unavailable browser storage recover to empty state. Ambiguous legacy `ln_read:` history is left untouched and is not imported, so prior browser-wide progress resets rather than being attributed to another account.
5. Home, Explore and Settings synchronize browser history, including popstate. Settings retains the direct-link form `/?view=settings`. Refresh and Back/Forward are covered without adding a router or replacing the integrated UI.
6. Personal-feed lists use the same indexed card metadata as Explore. Cards no longer load full feed payloads or editions. A thirty-feed regression asserts timestamps/star state and zero detail reads. Owner filtering and voter isolation remain enforced by the backend.

A passing CI run does not establish unrestricted public-beta readiness.
