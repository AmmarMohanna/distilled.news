## Product and subsystem ownership

8. Frontend preserved: minimalist visual styles, FeedEditor/source picker, explicit recommendation interaction, microphone title/interest input, dialogs, theme/account/settings flows and PWA assets.
9. Backend preserved: connector contracts and safety, Candidate Intake/receipts, immutable evidence, authorization/deletion/fencing, modern scheduler, private execution/VPC path, provider ceilings, semantic/Event/Storyline intelligence, communication ledger, EditorialPlan, approved-fact synthesis, grounding/fidelity/reader-witness verification, immutable publication and replay recovery. No frozen migration was rewritten. Frontend-era Worker push/sketch code and its duplicate historical migration were removed.
10. Create contract: `POST /api/me/feeds` accepts stable client id, title, interestProfile, explicit sourceInputs, publicFeedEnabled, updateIntervalMinutes, optional briefingTimeOfDay, language and inferred briefingTimezone. Internal naming follows existing conventions. It is a strict product schema; it does not accept style/depth/model/slug/salience controls. Sources must be present and supported. The server derives slug and translates to the richer internal configuration.
11. Edit uses the same endpoint and editor, loading actual approved sources first. Load failure prevents saving a destructive empty list. Existing slug/timezone are preserved. Removing sources revokes them through existing deletion/fencing semantics; retries retain stable Feed/source identities.
12. Privacy is enforced in shared public read resolution, search/detail/evidence/star paths, direct modern edition/evidence APIs and Explore filtering. Private anonymous reads return 404; verified owners retain access. Visibility changes alter exposure immediately. Public manifests exclude private Feed metadata.
13. Intervals are exactly 30, 60, 120, 360, 720 and 1440 minutes. They persist in existing `v1_briefing_interval_minutes`; the original live scheduler remains authoritative. Compatibility cadence is daily for 1440 and hourly otherwise.
14. Daily reveals Deliver at and persists the selected local HH:mm. Non-Daily hides it and uses the existing midnight anchor. Actual UI edits persisted **08:15**, rather than retaining/defaulting an older value.
15. Browser Intl inference persists IANA timezone; proof used **Asia/Beirut**. There is no normal timezone control, GPS or manual slug input. Next briefing is a server-calculated read-only boundary using the existing scheduling policy, including DST.
16. Writing style/depth, weekly/monthly and other internal editorial controls are absent from the ordinary Create/Edit flow. Internal compatibility fields remain; no destructive removal migration was added.
17. Explicit approved RSS selections become real connector-owned FeedSources and enrolled intake scopes. No interest-to-source substitution or legacy polling. Stable upsert avoids duplicate records. Existing source/Feed revision triggers fence obsolete work. Deployment retains the ten-source admission ceiling. New onboarding currently accepts public RSS URLs only; other connector runtimes remain intact but are not yet exposed through this clean onboarding endpoint.
18. Recommendation endpoint is authenticated, rate limited to two requests/hour/account, and opt-in. Enabled capability uses one ten-second, 400-token request, at most five normalized safe HTTPS suggestions, and never subscribes/fetches them. **Staging keeps it disabled** to preserve paid-provider settings. The real UI request returned 503 with a useful error; no source was added by recommendation.
19. Voice remains on Feed title and interest inputs, with browser-supported speech recognition and typed fallback. No backend voice field exists. Buttons were verified in the real browser; actual microphone capture was not attempted in headless Chromium.
20. The Feed API reads published modern editions and adapts immutable published claims/provenance to the existing presentation shape. It does not rebuild selection from current evidence/Events/Storylines/plans. Latest/history, publication timestamps, story prose, published source detail and loading/error states are available. Durable briefing request state distinguishes waiting, checking, quiet and failed; quiet is not presented as failure.
21. Citations retain original source URLs and supporting published provenance. Source detail opens an original BBC URL; internal revision ids are not primary user links. Browser assertions compared every displayed section's prose with the corresponding immutable published claims.
