# V3 backlog catch-up

`V3_BACKLOG_CATCHUP_ENABLED=true` enables bounded catch-up for automatic V3 reporting windows. It is enabled in the sources-QA configuration; absent/false keeps the previous scheduler behavior. Staging and production configuration are unchanged.

After an outage, the scheduler records up to 50 consecutive missed windows per pass using the feed's existing persisted policy. Every request retains its own exact start, end, intended delivery time, timezone, schedule marker and stable identity. Requests are recorded at the real observation time. The pass does not invoke models while there are still unrecorded intervals before the current close.

Once the current window exists, older unstarted V3 requests at least 15 minutes past their intended delivery (or close for retained schedules without a delivery label) may become `DONE / DEFERRED / SUPERSEDED_BY_LATER_WINDOW`. Each retains its original fields and a `catchup` record identifying the successor and policy. No edition, delivery receipt or quiet result is fabricated. At most 50 requests are deferred per pass; inference waits for further mechanical passes when that bound is reached. The 15-minute catch-up grace is separate from first-delivery preparation and collection-capacity deadlines.

The existing unresolved-window evidence path includes deferred windows. V3 therefore considers unpublished source material in the newest input without extending that input's reporting window, re-dating articles, or changing source identities. Carry eligibility preserves ordinary reports, meaningful late discoveries, and revisions of previously published evidence. Initial pre-subscription backlog and post-cutoff observations keep their existing exclusions. Published reader memory, source references, verification and provider admission limits remain unchanged.

Catch-up does not supersede legacy V2/unmarked requests, manual/evaluation/weekly windows, editions, verified V3 results, synthesis jobs, prior editorial plans, windows with model intents, explicit uncertain/frozen recovery waits or protected blocked work. A live semantic lease prevents deferral during preparation before the first paid intent. The target must be an unstarted closed V3 window without a frozen input/result. Decisions share the feed epoch/CAS fence used for model intent admission; a concurrent admission forces rechecking. A stale publication callback rechecks durable request state before freezing an input or admitting a model call.

No paid operations, reservations, settlements, leases, source collection jobs or checkpoints are deleted or reset. Started/uncertain work keeps its explicit recovery path and verified-result reuse. Unavailable source content does not become available because its reporting window was deferred. This is not a guarantee of instantaneous publication, factual accuracy or sustained capacity.

Apply additive migration `0084_v3_catchup_admission.sql` before enabling the flag. Its trigger rejects a new V3 intent for a catch-up-deferred window, including from an older Worker instance; the atomic model-reservation/intent batch rolls back before dispatch. It does not modify existing intents, charges or receipts. Catch-up refuses to supersede requests if the fence is missing. Selectors use existing pending-window, exact intent-budget and lease indexes plus the new relative-schedule watermark index; relative recovery reads the latest boundary instead of all historical request payloads. Maintenance reads pending metadata rather than full historical article/result payloads.

Validation covers bounded materialization and dispatch, opt-in compatibility, clock/creation-time precision, daily local delivery across DST, immutable paid holds, concurrent intent admission, active preparation, frozen targets, late-discovery/correction carry, stale deliveries, citations and repeated-result reuse. Local provider calls are mocked. Live rollout and publication evidence must be reported separately.
